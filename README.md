# SkyTrace ADS-B 空情台

SkyTrace 把树莓派上的 1090 MHz ADS-B 接收器变成一个长期运行的接收站，并把整理后的飞机状态、位置轨迹和原始 Mode S / ADS-B 报文上传到群晖。群晖只运行一个 Docker 服务，提供网页、API 和 SQLite 历史数据库。

## 已实现功能

- 实时地图：通过 WebSocket 推送最近 90 秒仍有信号的飞机与接收站状态；以最新 ADS-B 坐标、地速、航向、更新时间持续推算短时位置，并在新报文到达时平滑校正。动画刷新率随地图缩放调整，失联过久会停止外推。可在国内高德底图与国际 OpenStreetMap 之间切换：高德显示层使用 WGS-84 → GCJ-02 校正，OpenStreetMap 直接使用 WGS-84；切换时飞机、接收站、历史航迹和地图中心会一起转换，不会整体偏移。支持空白区域直接拖动、普通滚轮缩放以及手机触摸操作。
- 飞机资料：后台按 ICAO 地址和呼号查询 ADSBDB，并在 SQLite 缓存注册号、制造商、机型、注册所有人、航司及公开航线资料。同时显示旅客使用的 IATA 航班号和 ADS-B 中的 ICAO 呼号；航司、出发地和目的地按浏览器语言显示，中文浏览器优先使用中文名称，未收录的本地化名称自动回退到资料源原名。地图图标的悬停信息同样包含双航班号、航司和本地化航线。
- 手机快速信息：在触摸设备或窄屏页面点击地图飞机图标，会在地图底部显示轻量卡片，优先突出航司和机型，并附带双航班号、高度、速度及航向；点击“详细资料”才打开完整抽屉，点击地图空白处可快速收起。
- 历史档案：按 ICAO、呼号、注册号、制造商、机型、所有人或航司搜索曾经接收到的飞机。
- 飞机详情：查看历史航迹、累计报文量，以及逐条 Mode S / ADS-B 报文的位字段、解析值、中文含义、CRC 和学习提示。
- 可靠上报：树莓派按批次上传；批次具备幂等 ID，网络重试不会重复入库。
- 离线缓存：群晖或公网不可用时，批次暂存在树莓派 SQLite 队列，恢复后自动补传。
- 数据保留：原始报文和轨迹默认保留 90 天，可在 `.env` 调整。
- 自动恢复：服务端和客户端容器均配置 `restart: unless-stopped`。

## 数据链路

```text
RTL2832U / R820T USB 接收器
        ↓ 1090 MHz
树莓派 readsb（校验、解码、位置计算）
        ↓ 每 5 秒批量上报；断网写入本地队列
群晖 FastAPI 服务
        ├─→ ADSBDB（仅查询飞机/航班公开资料，结果写入本地缓存）
        ↓
../data/abs_d/adsb.sqlite3（历史数据库）
        ↓
实时地图 / 飞机档案 / 原始报文详情
```

## 快速部署顺序

1. 按 [群晖部署说明](DEPLOY_SYNOLOGY.md) 上传项目并执行 `sudo sh deploy-synology.sh`。
2. 脚本会生成 `.env`、随机上报密钥和 `client.env`。
3. 把生成的 `client.env` 与整个 `client` 目录复制到树莓派。
4. 按 [树莓派部署说明](DEPLOY_RASPBERRY_PI.md) 执行 `sh deploy-client.sh`。
5. 打开 `https://hive.hahapiggy.vip:38391`。

服务端和树莓派客户端需要一起更新。本版客户端会读取 readsb 的 `seen_pos`，分别记录“最后信号时间”和“最后位置时间”；只更新群晖而不更新客户端时，服务端会兼容旧数据，但连续航迹推算的时间精度会较低。

## 怎么验证飞机坐标确实对应地图

ADS-B / readsb 给出的经纬度是 WGS-84，高德国内底图使用 GCJ-02，不能把原始坐标直接画到高德瓦片上。网页只在显示层做 WGS-84 → GCJ-02 转换，数据库和 API 始终保留原始 ADS-B 坐标。

1. 点击实时飞机，在“坐标校验”中查看原始 WGS-84、实际绘制的 GCJ-02、位置报文时间和转换偏移。中国境内常见偏移约 300–700 米；显示偏移为 0 或出现第二次偏移通常说明坐标系配置有误。
2. 用固定地标做基准测试。例如天安门 WGS-84 `39.908823, 116.397470` 应转换为约 `39.910226, 116.403714`，偏移约 555 米。当前转换实现与该基准吻合到小数点后 6 位。
3. 最可靠的现场检查是填写天线的 WGS-84 坐标，确认网页上的接收站圆点落在天线所在建筑。`RECEIVER_LAT` / `RECEIVER_LON` 必须填写 WGS-84；不要直接复制高德或百度显示的坐标，否则网页会再次转换。
4. 对照其他航班网站时，要比较同一时刻的原始位置。飞机以 900 km/h 飞行时每秒约移动 250 米，第三方网站的延迟与插值会造成数百米差异；网页上的飞机图标还会在原始锚点之后做最多约 8–20 秒的短时外推，这是预期动画，不会写回数据库。

## 安全与容量

- 写入 API 必须使用部署时随机生成的上报密钥；网页和只读 API 默认不要求登录，适合放在自有局域网或由 DSM 反向代理负责访问控制。
- 默认端口为 TCP `38391`。
- HTTPS 直接使用脚本目录旁 `../SSL/privkey.pem` 和 `../SSL/fullchain.pem`，证书目录以只读方式映射进容器。
- 原始报文量取决于天线位置和空域繁忙程度。默认 90 天通常会积累数 GB 数据；存储较小时可把 `RETENTION_DAYS` 改成 `30`。
- SQLite 使用 WAL 模式。备份时建议先停止 `adsb-tracker-server`，再完整复制 `../data/abs_d`。
- 飞机与航线资料补全默认访问 `https://api.adsbdb.com`。查询在后台单线程限速执行，失败不会阻塞 ADS-B 上报；航线按呼号匹配，可能是计划或常见航线，并不等于本次飞行的实时航路。
